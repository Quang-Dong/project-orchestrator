# Workflow revision v02 — validation

This source revision adds attempt ownership and reconciliation guidance, project-bound selection checks, versioned metrics/trials, a read-only reporter and a local-first contribution path. The package remains unpublished. The initial report and manifest retain their original meaning; v02 does not rewrite earlier evidence.

## Observed checks

- 43 Python tests passed: 16 policy checks on the unchanged checker revision, plus 27 reporter checks after the final integration correction. This is local test evidence, not remote CI.
- Standard skill validator passed. Local CLI discovery and project/global copy installations passed in an isolated temporary project and fake user home. All 11 installed skill files matched the tested source; real installations and configuration were unchanged.
- A separate temporary development copy accepted a synthetic contribution change while the installed copy remained unchanged. A local proposal body was prepared; no fork, commit, push or PR was performed.
- Eight fictional coordination/contribution cases met the review rubric after correction. These are decisions on fixtures, not proof of runtime enforcement or live GitHub behavior.
- Public files were inspected and scanned for private project names, machine paths, session/account identifiers and raw private logs. Relative documentation links were checked. Detection and inspection reduce export risk but cannot guarantee all possible secrets are recognized.

## Actual takeover

Two separate sessions requested and observed as Luna Medium worked sequentially. The first froze a metrics checkpoint and its tests. The fresh second session verified the checkpoint hashes and continued from the task contract, source and handoff without reading the first conversation. Ambient environment/skill instructions were still present; this was not a sterile context experiment or a no-skill comparison.

The first full implementation did not pass independent acceptance. Review found validation, missing-data and read-only API defects. One worker repair round resolved that review suite. Final manager review then reproduced a cross-attempt partial-effort aggregation defect, added two regressions and made a narrow integration correction after the worker stopped. Worker artifacts remain frozen separately from the integrated version.

The final integrated reporter passes the same contract. Successful transfer of work was observed; first-pass autonomous correctness was not. A completed worker report must continue to enter review rather than acceptance. The final reporter groups missing effort conservatively and does not turn unknown values into complete totals.

## Decision and limits

Retain bounded artifact-based takeover and sanitized staging for this demonstrated scope. Comparative improvements in question count, time, token use or cost remain unproven. Trials without a comparable baseline are explicitly deferred with a next review trigger in the consuming project.

The checker validates supplied policy and runtime inventory. It does not authenticate approvals, establish runtime freshness, measure remaining budget or grant task-creation authority. The reporter validates records, not the truth of the supplied evidence. No production system, public contribution or installed distribution was changed by these checks.

See [v02 source manifest](skill-manifest-v02.json), [workflow cases](workflow-cases.json), [sanitized decisions](workflow-results-v02.json) and [contribution guide](../CONTRIBUTING.md). Private execution evidence and usage remain in the consuming project. Long-term effectiveness requires repeated comparable tasks with unchanged quality criteria.
