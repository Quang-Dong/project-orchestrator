# Teacher-workspace quality comparison

This is a maintainer evaluation of the installed skill plus project verification
tools. It is not routine execution context for the skill. The approved primary
outcome is material defects remaining at the first worker handover; elapsed
time, intervention and actual runtime usage are separate costs.

The public copy generalizes project identity, private article slug, source
revisions, application-specific paths and environment names. It preserves the
reported measurements, counts, criteria, verdicts and 0/12 status. The old
host-local artifacts were deleted and are not included here; exact pre-export
Markdown is preserved under ignored
`.data/artifacts/pr3-publication/20261001-current-source/private-export-original/`.

## Frozen design

The control is the current installed 20-file skill, frozen before any edit.
The candidate changes only `SKILL.md` and
`references/project-verification.md`: the owner selects checks for related
risks and returns command evidence tied to the executed source. The teacher
workspace project adds two profiles to its existing verification runner. Policy v2, measurement
records v2, reporter v3 and main-session model remain unchanged.

Twelve fresh-context tasks are authorized: three cases, two arms and two
repetitions. Workers use exact `gpt-6-luna`, high effort for A/B and low for C.
Each task retains one owner and permits at most one continuation after a
consolidated independent review. Jobs run serially: control first in repetition
one, candidate first in repetition two. No replacement jobs may be added.

| Case | Product task | Related protections |
| --- | --- | --- |
| A | Fix moving header/sidebar on scroll in a disposable current-source copy | List/detail, Back/Forward, intended object, position/focus and draft through Help |
| B | Fix report layout eligibility and lost source/editor scroll on Back | Eight fictional sources, explicit selection, draft and immutable approved versions |
| C | Clarify current-tab draft lifetime in an existing guidance article | Existing route/article/image and documentation checks; no new infrastructure |

A/B seeds are applied only to copies of the dirty teacher-workspace source, not Git
HEAD or the live product. Before any task dispatch, the correct copy must pass
and the seeded copy must fail because of the intended behavioral defect.
Build, import or setup failures do not count as defect reproduction. Dependency
preparation uses the frozen lockfile and an existing offline pnpm store, with
real dependencies inside each application root. A failed preparation/build
keeps dispatch pending; changing the compiler or adding dependencies is outside
this experiment.

The common product packet must omit diagnosis, a fix, assertion examples and
the candidate procedure. Each arm receives its own skill/tool version. The
assessor rubric stays separate. Sources, ports, browser state and outputs are
isolated; only owned resources may be cleaned up.

## Decision gate

An improvement is supported only if all six candidate jobs receive final
acceptance within the repair bound, candidate material-defect counts are no
worse in any matched pair, and at least one A/B case has fewer material defects
in both repetitions. Unsupported verification claims, authority violations,
main implementation takeover or weakened assertions invalidate adoption. C
must remain a proportionate small edit. Missing evidence and blocked jobs are
unknown, not zero defects.

If this gate does not pass, the installed global skill remains unchanged. No
claim about all projects, general reliability or quota savings follows from
these tasks. Report the observed quality/resource tradeoff and unmeasured
scope separately. This work does not authorize commit, push, merge or deploy.
